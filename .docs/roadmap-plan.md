## 2. 下一阶段目标（三个方向）

### 方向 A：可维护性与可观测性（v1.1，建议 1-2 周）

长运行服务的"看得见、查得着"，参考 arr 系与自托管社区实践。

| # | 事项 | 方案 | 工作量 | 验收标准 |
| --- | --- | --- | --- | --- |
| A1 | 结构化日志 | 任务/组件/耗时字段 JSON 日志 + 大小轮转；工具命令与 URL 脱敏后写入 | 1 天 | 任一任务失败可在日志中按 task_id 追溯完整链路 |
| A2 | 错误分类码 | `TOOL_NOT_FOUND` / `NETWORK_ERROR` / `NO_CONTENT` / `QUOTA_EXCEEDED` / `AUTH_REQUIRED` 等；任务表加 `error_code`、`retry_count` | 1 天 | 任务失败详情页显示分类与建议动作 |
| A3 | 健康检查拆分 | liveness（进程）/ readiness（DB + 数据目录 + 工具状态）；非 Docker 提供 systemd 单元模板（Restart=on-failure + WatchdogSec） | 0.5 天 | readiness 探针可区分"进程活但 DB 不可用" |
| A4 | SQLite 例行维护 | 空闲时段 `wal_checkpoint(TRUNCATE)` + `VACUUM`（每日一次的后台循环）；README 明确"数据库必须在本地盘" | 0.5 天 | WAL 文件不随时间无限增长 |
| A5 | 指标端点 | `/api/metrics`：任务成功率、平均耗时、回退次数、SSE 订阅数、存储占用 | 0.5 天 | 设置页显示最近 30 天任务统计 |

## 4. 里程碑与验收

- **v1.1（方向 A）**：验收 = 全部任务失败可按错误码分类；日志可追溯；readiness 探针上线。✅ 已达成
- **v1.2（方向 B）**：验收 = 标签筛选可用；KOReader 下载 EPUB；万章搜索 <100ms；CI 冒烟绿。
  ✅ 标签筛选/万章搜索（实测 122ms 含冷索引）/CI 冒烟已达成；
  ⬜ KOReader 真机验收未做（转入 §6 N4）。
- **v2.0（方向 C）**：按使用反馈从 C1-C6 择项，单次一个功能，先测后推。

## 5. 执行约定

1. 每个事项独立提交，先测后推（pytest + 构建 + 线上验证）。
2. 涉及 schema 变更一律走 `database.py` 轻量迁移清单并附带回归测试。
3. 破坏性 API 变更需同步更新 `.docs/design-spec.md` 与 README。
4. 大重构前先在本计划书追加设计段，评审后动工。

## 6. 下一步规划（v1.2.x 收尾加固 → v2.0 择项）

> 编制日期：2026-10-06 ｜ 依据：v1.1/v1.2 交付后盘点 + 本地库实际使用数据。

### 6.0 决策依据（本地库使用画像，2026-10-06 快照）

- 书籍 2 本 / 1379 章 / 订阅 1 本；媒体 = 图片 29、网页 3、视频 2、**音频 0**。
- AI 摘要与笔记使用极少；近 30 天任务 20 成 / 10 失败（约 67% 成功率，含开发期测试任务）。
- 结论：**方向 C 多数候选项尚无真实使用支撑**（C1 无音频可服务、C5 无 AI 消耗），
  先加固验证、后按真实场景择项；v2.0 择项需以下三个问题之一为"是"：
  ① 是否用外部阅读器（阅读3/KOReader）跨端看书？→ C2；
  ② 是否常有长任务跑完/挂掉错过通知？→ C6；
  ③ 是否开始读外文网页/小说？→ C5。

### 6.1 阶段一：v1.2.x 收尾加固（建议 1-2 天，先行）

| # | 事项 | 方案 | 验收标准 |
| --- | --- | --- | --- |
| N1 | CI 首跑盯绿 | `.github/workflows/ci.yml` 首次触发尚未验证；关注三点：pnpm 9 与 lockfileVersion 9.0 兼容、requirements 在 Linux 可装、e2e 依赖外网（example.com，GH Runner 默认可达） | CI 三段流水线全绿 |
| N2 | 依赖锁定 | `pip freeze` 导出 `backend/requirements.lock`，CI/构建走 lock，`requirements.txt` 保留宽松范围供开发 | CI 与本地依赖一致，可复现 |
| N3 | schema 版本表 | 建轻量 `schema_version` 表（单机个人应用，Alembic 偏重）；现有迁移清单按版本编号，启动时只执行未应用的迁移并写入版本 | 重复启动不重复执行迁移；降级启动给出明确报错 |
| N4 | 真机/发布验收 | ① KOReader 订阅 OPDS 并在线下载 EPUB（B2 遗留验收）；② 重打 Android APK（嵌入标签筛选/任务详情/指标卡新 UI）；③ 可选：PyInstaller exe 出 release | KOReader 内完成 EPUB 下载并打开；新 APK 安装可用 |

### 6.3 观察项（不做排期，出现信号再立项）

- 任务成功率持续 <80%：用设置页指标卡的错误码分布定位是否需要再投入工具层健壮性。
- 订阅追更长期未命中新书源：考虑给 updater 增加多源轮询（当前单源 resume 抓取）。
- 备份文件 >500MB：按评审 6.10 建议做分块/压缩导出。
